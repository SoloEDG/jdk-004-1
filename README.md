# VOID SIGNAL · 虚空信号

## 安装

Node.js 22.12 或更新版本。

```sh
npm ci
```

## 本地启动

```sh
npm run dev
```

打开终端显示的本地地址。

## Docker 启动

```sh
docker compose up --build
```

打开 http://localhost:8084 。可通过 PORT 环境变量修改端口。

## 测试

```sh
npm test         # 单元测试（引擎规则 + 回放确定性）
npm run typecheck
npm run build
```

## 行动回放（Action Replay）

行动只记录**输入**而非每帧战场，因此长局文件不会随弹幕/敌人数量膨胀：

- 每个固定步长（1/60 秒）把移动方向、指针瞄准、是否开火打包成 4 字节，base64 存储；
- 升级是离散事件，记录发生的 tick、当时候选与玩家选择；
- 回放用**原始随机种子**重建战场，按相同规则与固定步长重放输入。
  随机调用顺序由相同规则与输入保证一致，无需保存任何实体快照。

关键约束与安全策略：

- `src/shared/rules.ts` 的 `RULES_VERSION` 固定规则版本。任何改变模拟结果的改动
  （伤害、生成、掉落、随机调用次数/顺序、固定步长）都必须递增该版本，
  旧回放会被拒绝播放，而不是静默产生对不上的画面。
- 每个回放带 FNV-1a 校验和；输入帧数不符、升级候选发散、校验和失配、
  版本不支持都会**中止播放并保留原档案**，绝不静默跳过导致统计对不上。
- 回放结束会比对重放结算与录制战绩（时长/波次/等级/击杀/伤害/胜负）。
- 回放战场标记 `replay`，其结算**不新增真实战绩**、不写入 localStorage。
- 旧档案（无 `hasReplay`）只展示原汇总，不提供播放/导出入口。
- 档案面板支持播放、逐帧定位（拖动/单步/升级点跳转）、导出 JSON 与导入回放。
